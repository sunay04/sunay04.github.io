# 作品集 AI 助手

## 使用方式

编辑作品时，点击「检查作品完整度」「优化简介」，或文本块上的「改善这段」。
助手会读取当前作品的简介、正文和成果文字；不会读取图片、视频、外部链接、其他作品或 GitHub 令牌。
补充说明可填写真实职责、创作限制、目标方向，也可回答上轮建议的问题。
点击「生成建议」才会把这些文字交给 DeepSeek，输入不会自动上传。

结果包含原文、建议文案、修改理由和最多五个待补问题。逐条「采纳到草稿」后，继续使用原来的预览和发布流程。
助手面板中的已采纳记录允许逐条撤销；目标文字已被其他编辑修改时，禁止覆盖或撤销。
关闭面板和切换预览保留当前作品的本轮建议；切换作品或刷新会清空 AI 建议、补充说明和撤销记录，已采纳的文字仍保存在现有浏览器草稿中。
第一版只改善简介与正文，不生成图片、不增加块、不修改布局、不自动发布。

## Vercel 配置

在项目 Settings → Environment Variables 设置：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-flash
```

`DEEPSEEK_MODEL` 可省略，默认 `deepseek-flash`。密钥不要使用 `VITE_` 前缀，也不要写入 Git。
选择实际使用的环境（Production / Preview），保存后重新部署。
项目原有 GitHub OAuth、SESSION_SECRET 等配置仍然需要保留。
接口沿用现有 `/api/:path*` 重写与 GitHub 仓库编辑权限，匿名访客和没有编辑权限的用户不能调用。
未配置密钥时显示明确提示，普通编辑功能继续工作。

本地 `npm run dev` 仅启动前端；`/edits?demo=1` 是 UI 预览，不会获得真实 API 权限。
真实联调请使用配置好 OAuth 与环境变量的 Vercel Preview 部署，登录后生成一次建议。
不要为本地模拟登录添加服务端鉴权绕过。自动化测试通过模拟上游响应验证成功、失败和撤销行为，不消耗真实 API 额度。

## 实现和限制

- `api/index.ts`：只在服务端读取环境变量。
- `api/_github.ts`：复用已有会话与编辑权限，分发 AI 请求。
- `api/_ai.ts`：受控提示词、严格同源 POST、输入大小限制、DeepSeek 调用及结果校验。
- `src/editor/ai.ts`：字段白名单、结构校验、按作品 ID 和原文比较的采纳/撤销。
- `src/editor/AiAssistant.tsx`：上下文选择、状态提示、问题补充、采纳和撤销。

输入上限为 120 KB、60 个文字字段、24000 字正文总量、4000 字补充说明；单字段最多 12000 字。
模型输出必须引用存在的可编辑字段且准确复述原文；段落模式不能修改其他字段。
模型判断仍需作者核对，结构校验不能证明事实真实。

服务端上游超时 50 秒，前端超时 60 秒，Vercel 函数最大时长配置为 60 秒。
取消/切换作品会中止浏览器请求并忽略迟到结果；服务端在运行环境传播断开信号时尝试终止上游调用，不能保证取消后供应商不计费。
每个函数实例按登录用户限制一分钟六次、一次一个请求。这是尽力限流，多实例和冷启动不共享计数，不能作为全局费用上限。
若开放给更多协作者，应增加共享存储配额或 Vercel Firewall 限流，并在供应商侧控制账户预算。
应用不记录密钥、提示词或作品正文日志；调用服务商的数据处理规则由 DeepSeek 提供。
